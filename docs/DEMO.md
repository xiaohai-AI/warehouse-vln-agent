# 演示脚本（headless，约 12–15 分钟墙钟）

> 这台机器**没有显示器**，全程 `gui:=false`，所有结论都用**数字**说，不靠 RViz。
> 仿真实时因子 RTF≈0.44（1 秒仿真 ≈ 2.3 秒墙钟），下面标的都是**墙钟**。
> 每一行"预期输出"都是从真跑日志里抄的，不是示意。

演示要证明的三件事：

1. **一条自然语言能走完**：理解 → 语义图 → 导航 → 现场核验 → 回答（§1）
2. **判据真的在判**：故意把相机俯仰推过容限，它必须**判错并自己报出来**（§2）
3. **动态障碍能处理**：Nav2 在障碍挡路时把路径掰开绕过去（§3）
4. **账对得上**：16 条判据、产物、复现命令三者对齐（§4，30 秒）

## 1. 正常一单（约 4 分钟）—— 讲"它能自己走完，并且自己核验"

```bash
UTT="去 C-L-08-1" VERIFY=depth POSE=odom make p6-demo
```

**预期输出（关键行，按出现顺序）**

```
[p6] 仿真就绪（/odom 有 1 个发布者，等了 9 s）
[p6] 相机就绪（/stereo_left 有 1 个发布者，等了 2 s）
[act] seq=1 → C@08 观测位 (-10.80,-2.15) yaw +1.57 | 航段 9 段 / 20.2 m / RTF≈0.44 / 预计墙钟 145s
…
[observe] 投影位姿=odom (-10.86,-2.17) yaw +1.560 | 真值 (-10.86,-2.08) yaw +1.546 → 误差 0.09 m / +0.8°
观测详情   C-L-08-1: empty（比格口(1.35m+0.40m)更近的最大连通块 0 px（共 0 px，占 0.0%；…）
到达位姿   (-10.86, -2.08) yaw +1.546  末段误差 0.09 m
原因码     OK
打分(真值) {… "truth_occupied": false, "obs_occupied": false, "occupied_match": true, "class_match": null}
RESULT: PASS
```

**讲解要点（三句话）**

- `航段 9 段 / 20.2 m`：不是直接开过去，是按**语义图**逐段走（D23-1）——点对点开直线会横穿货架。
- `投影位姿=odom … 误差 0.09 m / +0.8°`：用的是**里程计估计位姿**，真值只用来**量误差**，不是拿来导航（D28）。
- `occupied_match: true`：现场双目深度判"空位"与真值一致 —— 这是**核验**，不是模型口头保证。

**本段要主动说的限制**：`class_match: null` 不是我偷懒 —— 类别在 320×240 / 1.75 m 下
S 与 M 的像高只差 9 px，**已明确降级为参考**（D25/L2）；而"这一格是哪一格"视觉上根本不可判
（画面无货位编号，**L1**）。

## 2. 故意让它失败（约 4 分钟）—— 讲"判据不是摆设"

在**空位** `C-L-08-1` 上把相机**下俯 7°**（越过实测容限）。空位本该判 `empty`（基线 0 px），
俯太深会让投影窗口滑到货位下方、把地面/层板框进来 → **假阳性**：

```bash
CAM_PITCH=-7.0 UTT="去 C-L-08-1" VERIFY=depth POSE=odom bash scripts/p6_demo.sh; echo "退出码=$?"
```

> **为什么这里直接跑 `scripts/p6_demo.sh` 而不是 `make p6-demo`**：`make` 会把任何配方失败
> **归一成退出码 2**（真值只出现在 `make: *** [Makefile:108：p6-demo] 错误 3` 那行），
> 于是 `$?` 拿到的是 2 而不是 3 —— 退出码契约（0/3/1）在 `make` 后面失效。
> 要演示"退出码 3"就必须绕过 make；日常跑用 `make` 没关系，看 `[p6] demo 退出码 3` 那行即可。

**预期输出**

```
[observe] 相机俯仰=-7.0°（模型按 0 投影，等效竖直偏 -19.6 px）
观测详情   C-L-08-1: occupied（…最大连通块 1262 px（共 1262 px，占 15.5%；门槛 250 px / 1.0%）…）
原因码     VERIFY_MISMATCH
回答       到了位置，但现场看到的和地图记录不一致（原因码 VERIFY_MISMATCH），已标记为待复核。
打分(真值) {… "truth_occupied": false, "obs_occupied": true, "occupied_match": false …}
RESULT: PASS_WITH_WARN（观测与真值不符）
退出码=3
```

> 注：`等效竖直偏 -19.6 px` 是按 `f·tan(pitch)`（f=160 px）算的，与实测的 `+2° → +5.6 px` 同一公式；
> 块大小**新判据下实测 1085 px / 1262 px**（旧判据是 519 / 830 px —— 判据版本换了，数字跟着换，
> 但都远大于门槛 250 px（2.1× / 3.3×），所以这个案例是**稳的**（对比 `+2°` 的 228 vs 282 px 骑线）。
> 产物：`results/depth_dumps/C-L-08-1_20261102T222657.npz`（1262 px）/ `…T183018.npz`（1085 px），
> 复算见 `results/verify_audit.json`（`pitch` 段，带 `rule_id`）。
>
> **为什么不用 `+2°` 那个点当演示**：它骑在门槛上。实测同一角度两次：
> 格口 **1.41 m → 228 px（判错）**、格口 **1.33 m → 282 px（判对）** —— 停位差 8 cm 就能翻转。
> `−7°` 的假阳性是 1085–1262 px（门槛 250，余量 4–5 倍），才算"稳的失败案例"。
> 这条距离依赖本身也是发现：**仰侧容限随停位距离浮动**（见 `DECISIONS D29 续 2`）。

**这段要讲清的三点**

1. **退出码 3 是专门为这种情况设计的**（D26）：`0` 到达且核验一致 / `3` 到达但**观测与真值不符** /
   `1` 失败。绝不把"看错了"混进 PASS。
2. **两侧失效性质不同**（D29）：仰 = **漏检**（窗口落到货的上方，块变小）、俯 = **假阳性**
   （窗口滑到货位下方框到地面/层板）。所以仰侧要用**有货格**测、俯侧必须用**空位**测。
3. **安全带是实测定版的，两端都有真跑钉住**：`−4° ≤ pitch ≤ +3°`（新判据 ztop0.85、位姿归一后；旧判据下是 −5…+2）。仰侧 +3°→311 px 判对、**+4°→126 px 漏检**；俯侧 −4°→17 px 判对、**−5°→419 px 假阳性**（空位）。注意：带内俯仰 + 位姿误差 ≥0.3 m 仍会假阳性（实测 0.44 m 漂移时 −3° 出 994 px）。最优安装 −2…−3°（离两侧边界各 ≥5°）；等效竖直偏 ≈ `f·tan(pitch)`
   （f=160 px）。不是"调参调到能过"。

**可选加演（30 秒，离线）**：地址不存在时它必须**拒绝**而不是瞎猜 ——

```bash
DRY=1 UTT="去 C-L-99-1" make p6-demo | tail -6
```

实测输出：

```
原因码     NO_SLOT
回答       没有这个货位（原因码 NO_SLOT）。请确认巷道/bay/层号。
RESULT: PASS
```

**`RESULT: PASS` 在这里是对的**：期望行为就是"**带原因码拒绝**"，而不是静默换一个位置糊过去
（D24；这也是 P6-1 里 69/69、静默猜 0 的那条纪律）。要强调的是**原因码**和那句明确的回答，
不是 PASS 两个字。

## 3. 动态障碍：Nav2 绕行（约 3 分钟）—— 讲"不是停着等，是绕过去"

```bash
cd ~/Project/depot-vln
CART_Y=-1.25 bash scripts/avoid_probe.sh      # 受控台：车摆在机器人实际路径上
```

**预期输出（判决五行，2026-11-03 实跑）**

```
[dyn] /scan 最近回波（挡路期间）: 0.72 ~ 2.99 m
[dyn] /local_costmap/costmap:  推车位附近致命格最多 302 个（全图 1623 个），最近距离 0.08 m —— **标上了（就是推车本体）**
[dyn] /global_costmap/costmap: 推车位附近致命格最多 551 个（全图 301478 个），最近距离 0.08 m —— **标上了（就是推车本体）**
[dyn] 路径在 x=-26.00 处 y≈-1.88，推车在 y=-1.25 → 偏出 0.63 m（<0.5 m 视为没绕）
[dyn] 挡路期间机器人 x: -27.55 → -21.05（推进 +6.50 m，共 25 个采样）
[probe] 结果：BYPASSED（车仍挡路时机器人越过 x=-26.0，且路径偏出 0.63 m）
```

**为什么这几行才算"真绕"**（每一行都对应一次踩过的坑）：

| 行 | 它挡住什么假象 |
|---|---|
| `/scan` 最近回波 ~0.7 m | 证明**传感器**看见了（否则先查雷达，不该怀疑规划器）|
| **两层** costmap 的 `最近距离 0.08 m` | 证明障碍**真的进了 costmap**（局部标上、全局没标上时，规划器会规划穿过障碍的直线 —— 这是绕了七轮的根因）|
| 路径到车心 **0.63 m ≥ 0.61** | 证明路径**不进膨胀区**（0.26 半宽 + 0.35 inflation）；静态地图自带的斜线最多 0.45–0.77 m，单看这条会被骗 |
| 机器人推进 **+6.50 m** | 证明车**仍挡路**时机器人已经过去（否则只是"停车等待"）|

**最硬的证据是 A/B**：同一个车、同一个机器人、同一套采样，**只让障碍进全局 costmap**
（`obstacle_layer` 的 `raytrace/obstacle_max_range` 从 25/12 改到 8/4 等），
路径就从 **0.40 m（穿进膨胀区）** 变成 **0.63 m（绕开）**，机器人从"停滞/擦蹭"变成"通过"。

**讲的时候要主动交代的两点余量**（别让人以为很宽裕）：

- 余量只有 **+0.02 m**（0.63 vs 0.61）—— `cost_scaling_factor 2.0` 让路径贴着膨胀边界走；
- 长巷道里同样的绕行需要**障碍挡够久**（`DYN_HOLD=15`）：4 秒时规划器也绕了 0.62 m，
  但机器人只推进 0.85 m 就等障碍离开 —— **来不及横移**，不是不会绕。

**如果想把绕行放进整单演示**（约 8 分钟）：

```bash
NAV=1 DYN=1 DYN_HOLD=15 UTT="去 C-L-08-1" VERIFY=depth POSE=odom make p6-demo
```

预期：`[p6] nav2 绕行判据：越过=1、路径偏出=0.66 m（需 ≥0.61）`。
**注意这一单的 `verify` 可能报 `VERIFY_MISMATCH`**（本次实跑 456 px 假阳性）——
因为绕行使 odom 漂移从 0.03–0.14 m 增到 0.20 m，投影把格口放偏、判定窗口圈进隔壁货。
这是**已知耦合缺陷**（`LIMITATIONS L8/L24`），如实讲，不要当成避障失败。

## 6. 万一某行没出现（现场排障表）

| 现象 | 含义 | 处置 |
|---|---|---|
| 卡在 `Nav2 栈 240 s 未就绪` | 起栈失败（不是"慢"） | 看 `results/probe_stack.log` 尾部；常见是 `/scan` 没发布者 |
| `Goal was rejected` | lifecycle 还没全部 active | 已在脚本里等 `controller/planner/bt_navigator`，若仍出现看 `TROUBLESHOOTING §35.3` |
| 脚本打印两行就 `已杀死` | 脚本名含 `nav2_`，被栈自己的 `pkill -f "[n]av2_"` 杀了 | 改名（§35.1） |
| `[dyn] 超时：机器人始终没靠近` | 机器人没动（多半 act 失败），实验无效 | 先看 demo 的 `原因码`，别看障碍结论 |
| `安全层压住 0 次` 却说"正常" | **空结论**：必须先在 `results/p6_guard.log` 里看到 `[GUARD] 就绪` | 没有"就绪"就是进程没在跑（§34） |
| `RESULT: PASS_WITH_WARN` | 到达了但**观测与真值不符**（退出码 3）| 这是**判据在做它该做的事**，不是脚本坏了 |
| `make docs-check` 报 FAIL | 文档和产物数字漂了 | 别手改 `ACCEPTANCE.md`，重跑 `make accept` |

## 7. 一句话收尾

> 16 条判据全部有真跑或离线证据，三个命令可复跑（`make accept` / `avoid_probe.sh` / `make p6-demo`），
> 每条结论都能追到 `results/` 里的具体文件；四条能力边界写在 `docs/LIMITATIONS.md`，
