# 限制清单（唯一权威）

> 这份文件只写**已知不行/未验证**的东西。凡是这里没写的"能跑通"，都对应
> `make ci` 里一条会红的断言，或 `results/` 里一份带复跑命令的产物。

## A. 感知与语义（最主要的一条）

**A1 · 库存覆盖率只有 8%。** `results/inventory.json` 当前来自 SEG-2 的 46 个观测
（46/576 货位）。原因：相机只采了 A 巷、且第 2 层被层板遮挡物理不可见。
后果：属性类问题（"哪面有油桶""纸箱最多的货架"）在真实库存下**只能回答"没看过"
或变成歧义**，因此 `make bench-perception` 是 35/54（attribute 类 0/14），而非 100%。

> 这不是判据放松，而是把原来"用真值喂语义地图"的假象拆掉后的真实起点。
> 要提升，得改感知（多采几条巷 / 抬相机 / 加层板下的补拍），不是改语义层。

**A2 · `UNOBSERVED` 不会主动追问。** 现在它是"拒绝 + 说明原因"。
更好的行为是"我没看过 A-R 面，要不要我去看看"。没做。

**A3 · 第 2 层不可见。** 相机在 0.274 m、层板在 1.75 m，平视物理上看不见上层。
`seg2_detect.py` 只评下层，上层 288 个货位状态永远是"未观测"。

**A4 · 类别判定只在 1.75 m 处可信。** `carton_s` 与 `carton_m` 在该距离像高只差 9 px，
上层/远距离不可区分。

## B. 语言层

**B1 · 规则后端不支持相对/外观表达。** "左边数第三个货架""蓝色的大箱子"
只会退化成 `UNKNOWN_INTENT` 或按类别泛化（"蓝色的大箱子" → 全部 carton）。
支持这些需要 LLM 后端 + 视觉属性，未做端到端验证。

**B2 · LLM 后端只在"落地校验"层面验证过，没有跑满基准。**
`LLMNLU` 会丢弃原话里无依据的槽位并记账（`stats()["dropped"]`），
但三个本地模型的实测通过率、延迟、回退率**本轮没有重测**。重构前的记录
（qwen2.5:7b 72.5%、qwen3-vl 75.4% 且 34–56 s/条）见 `docs/archive/STATUS.md`。

**B3 · 词表是闭集。** 类别来自 `config/semantics.yaml`；闭集外的物体靠
`lexicon.unknown_objects` 显式列出才会被识别成"未知类别"，没列出的生造词会落到
`UNKNOWN_INTENT`。

**B4 · 中文/英文之外的表达未覆盖。**

## C. 导航与仿真

**C1 · 本轮没有重跑 Gazebo 侧判据。** M1（速度跟踪）、M2（侧移入库）、S1（双目深度）、
SLAM-1（S1/S3/S4/S5）、SEG-1/SEG-2、P6-2 的真跑数字都是**重构前**的，
证据在 `docs/archive/REPORT.md` 与 `results/*.json`。
本次只保证：这些脚本**语法可编译**、依赖的常量已改为从配置派生、离线链路可跑。

**C2 · 定位仍是"静态图 + 固定/真值锚定"。** `static_map_pub` 用
"起车时真值位姿 − odom 位姿"算 map→odom；没有真值时退回出生点固定偏移。
AMCL 实测比纯 odom 差（0.191 → 0.587 m），所以默认不用。真正的 SLAM 重定位没做。

**C3 · 车道偏移是场地事实，不是规划出来的。** `config/nav.yaml:lane_offsets`
（当前为空；C 巷曾用 0.55 绕开叉车）需要人按现场障碍物配置。没有自动绕障的重规划。

**C4 · Nav2 启动偶发 rmw 超时**（get_state 无响应），重试可恢复。

**C5 · 仿真非实时**：带双目 RTF≈0.44，所有采集速度按实测 RTF 定。

## D. 评测

**D1 · 基准只有 54 条**，四类均衡，人工编写。样本量足以发现结构性错误，
不足以谈"置信区间"。

**D2 · `make bench` 默认用**显式替身库存（`provider=sim-sampled`，覆盖率 100%）。
它衡量的是"语言 + 澄清 + 拒绝"三层，**不是**感知准确率。任何引用这个数字的地方
都必须带上 `sim-sampled` 标签。

**D3 · 静默猜错的判定**：期望澄清却没问就开过去、或期望拒绝却开过去了，算静默错。
"问不出来而拒绝"算失败但**不算**静默猜（两者分开统计，见 `runner.py`）。

## E. 工程

**E1 · 仓库里仍有一批一次性采集脚本**（`s3_*`、`avoid_probe.sh` 等），
它们各自对应一个已归档的判据。保留是为了可复跑，但不在 `make help` 的主路径上。

**E2 · 没有真实机器人的验证**（SPEC 非目标：sim-to-real 不在本期）。

**E3 · Python 3.10 + ROS Humble 锁定**；Jazzy 迁移未做。

## A5 · SEG-2 检测器尚未适配当前世界（**新的阻塞项**，2026-11-04 发现）

把采集扩到全巷道时发现：**新采的帧喂给 `seg2_detect.py` 会检出 0 个物体**，
而用同一份代码跑 2026-10-29 的旧帧仍然 precision/recall = 1.000（15/15）。
所以问题不在检测代码，而在**世界变了**：

* 2026-11-03 的 `make world` 给每个货位加了**编号牌**（`make_slot_labels.py`）。
  level-1 的牌子底在 `deck_z + 0.87 = 1.02 m`，正好落在原来 level-1 的检测带
  `(0.17, 1.60)` 里；牌子是一整排连续前景，形态学闭运算后横向连成 2.4–2.6 m 的大块，
  超过尺寸闸门（≤1.15 m）→ 全部判成"没有货"。
* 已经做的两处修复：
  1. 层带上界改成由 `slot_signs.band_z()` 派生（level 1 → 1.01 m），编号牌不再进带内；
  2. 货物深度带重标为 `(1.33, 2.35)` —— 半深货位把货物**退到了货架前沿之后**
     （前沿 ~1.34 m，货物 1.33–2.30 m），旧的 `(1.10, 1.55)` 只框住"前沿那条连续横梁"。
     这条用 `--d-lo/--d-hi` 扫参数、以 A 巷 34 个占用货位为真值标出来的。
* **当前实测（A 巷 48 帧）**：precision **1.000**、recall **0.529**、类别 top-1 **0.778**、
  错格率 0%。即"不再误报，但漏一半" —— 仍不达 SPEC（recall ≥0.85）。
  归因：货物退深之后，相邻货位的货在图像上更容易连成一块，被尺寸闸门（≤1.15 m）整块丢掉；
  纯靠调深度带已经到极限（1.30→11 TP、1.33→18 TP、1.35→16 TP，非常敏感）。
* 下一步（未做）：把分割从"固定深度带 + 连通域"改成"按 bay 的横向窗口切分后再求连通域"，
  并让尺寸闸门随深度自适应（同一个箱子在 1.3 m 和 2.3 m 处像素宽度差 1.8 倍）。

结论：**采集链路是好的**（A 巷 48/48 帧、位姿/朝向自洽），**打分链路需要按新世界重新做分割**。
