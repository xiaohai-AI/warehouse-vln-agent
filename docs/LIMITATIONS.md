# 限制清单（唯一权威）

> 这份文件只写**已知不行/未验证**的东西。凡是这里没写的"能跑通"，都对应
> `make ci` 里一条会红的断言，或 `results/` 里一份带复跑命令的产物。

## A. 感知与语义（最主要的一条）

**A1 · 库存覆盖率只有 8.3%。** `results/inventory.json` 当前来自 SEG-2 的 48 个观测
（48/576 货位）。原因：`results/seg2.json` 只汇总了 A 巷下层；B 巷已采 39 帧、
C 巷断点 32 帧，尚未纳入检测产物（C 另见 A6）。后果：属性类问题（"哪面有油桶""纸箱最多的货架"）
在真实库存下**只能回答"没看过"或变成歧义**，因此 `make bench-perception` 是 36/54
（attribute 类 1/14），而非 100%。

> 这不是判据放松，而是把原来"用真值喂语义地图"的假象拆掉后的真实起点。
> 要提升，得改感知（多采几条巷 / 抬相机 / 加层板下的补拍），不是改语义层。

**A2 · `UNOBSERVED` 不会主动追问。** 现在它是"拒绝 + 说明原因"。
更好的行为是"我没看过 A-R 面，要不要我去看看"。没做。

**A3 · 第 2 层不可见。** 相机在 0.274 m、层板在 1.75 m，平视物理上看不见上层。
`seg2_detect.py` 只评下层，上层 288 个货位状态永远是"未观测"。

**A4 · 类别判定只在 1.75 m 处可信。** `carton_s` 与 `carton_m` 在该距离像高只差 9 px，
上层/远距离不可区分。

## B. 语言层

**B1 · 规则后端不支持相对/外观表达。** "左边数第三个货架""蓝色的大箱子"
只会退化成 `UNKNOWN_INTENT` 或按类别泛化（"蓝色的大箱子" → 全部 carton）。
支持这些需要 LLM 后端 + 视觉属性，未做端到端验证。

**B2 · LLM 后端只在"落地校验"层面验证过，没有跑满基准。**
`LLMNLU` 会丢弃原话里无依据的槽位并记账（`stats()["dropped"]`），
但三个本地模型的实测通过率、延迟、回退率**本轮没有重测**。重构前的记录
（qwen2.5:7b 72.5%、qwen3-vl 75.4% 且 34–56 s/条）见 `docs/archive/STATUS.md`。

**B3 · 词表是闭集。** 类别来自 `config/semantics.yaml`；闭集外的物体靠
`lexicon.unknown_objects` 显式列出才会被识别成"未知类别"，没列出的生造词会落到
`UNKNOWN_INTENT`。

**B4 · 中文/英文之外的表达未覆盖。**

## C. 导航与仿真

**C1 · 大部分 Gazebo 判据没有再跑。** M1（速度跟踪）、M2（侧移入库）、S1（双目深度）、
SLAM-1（S1/S3/S4/S5）、SEG-1、P6-2 的真跑数字都是**重构前**的，证据在
`docs/archive/REPORT.md` 与 `results/*.json`。**例外是 SEG-2**：2026-11-04 已按新世界
重做并达标（见 A5/A6）。本次只保证：这些脚本**语法可编译**、依赖的常量已改为从配置派生、
离线链路可跑。

**C2 · 定位仍是"静态图 + 固定/真值锚定"。** `static_map_pub` 用
"起车时真值位姿 − odom 位姿"算 map→odom；没有真值时退回出生点固定偏移。
AMCL 实测比纯 odom 差（0.191 → 0.587 m），所以默认不用。真正的 SLAM 重定位没做。

**C3 · 车道偏移是场地事实，不是规划出来的。** `config/nav.yaml` 当前
`lane_offsets: {C: 0.55}`（导航绕开 C 巷 bay5 的叉车）、
`capture_lane_offsets: {C: 0.30}`（采集路线），都需要人按现场障碍物配置。
没有自动绕障的重规划。

**C4 · Nav2 启动偶发 rmw 超时**（get_state 无响应），重试可恢复。

**C5 · 仿真非实时**：带双目 RTF≈0.44，所有采集速度按实测 RTF 定。

**C6 · 控制时基必须按 RTF 折算（已修，但换机器要重新看）。**
gz 带相机渲染时 RTF≈0.22。原来转向的"脉冲时长"按仿真角速度算、却用 `time.sleep` 按墙钟执行，
于是每个脉冲只完成预期转角的 22%：实测 180° 要 60 s 以上、仍常留 50–140° 残差，
B 巷因此丢了 9/48 帧。现在 `align_to` 每段脉冲后用真值实测"到底转了多少"，EMA 更新
rad/墙钟秒再定下一段长度（与 RTF 无关）。实测同一场景：

| | 转身耗时 | 残差 | 丢帧 |
|---|---|---|---|
| 修复前 | 60 s+ | 50–140° | 9/48（B 巷） |
| 修复后 `turn_rate=0.9` | **21–32 s**（180°） | **0.9–4.2°** | **0/4**（C-23/24 实测） |
| 修复后 `turn_rate=1.5` | 19–50 s（不稳） | 0.2–4.7° | **2/4**（超调） |

结论：`turn_rate=0.9` 是当前仿真下的甜点；再高会超调丢帧。换机器/换渲染负载后
先用 `--bays 23-24` 这种两格试点复测，别直接跑全巷。

## D. 评测

**D1 · 基准只有 54 条**，四类均衡，人工编写。样本量足以发现结构性错误，
不足以谈"置信区间"。

**D2 · `make bench` 默认用**显式替身库存（`provider=sim-sampled`，覆盖率 100%）。
它衡量的是"语言 + 澄清 + 拒绝"三层，**不是**感知准确率。任何引用这个数字的地方
都必须带上 `sim-sampled` 标签。

**D3 · 静默猜错的判定**：期望澄清却没问就开过去、或期望拒绝却开过去了，算静默错。
"问不出来而拒绝"算失败但**不算**静默猜（两者分开统计，见 `runner.py`）。

## E. 工程

**E1 · 仓库里仍有一批一次性采集脚本**（`s3_*`、`avoid_probe.sh` 等），
它们各自对应一个已归档的判据。保留是为了可复跑，但不在 `make help` 的主路径上。

**E2 · 没有真实机器人的验证**（SPEC 非目标：sim-to-real 不在本期）。

**E3 · Python 3.10 + ROS Humble 锁定**；Jazzy 迁移未做。

## A5 · SEG-2 检测器已适配当前世界（2026-11-04 结案）

把采集扩到全巷道时曾出现"新采的帧全部检出 0 个物体"，而同一份代码跑 2026-10-29 的旧帧
仍然 15/15。根因是世界变了，不是代码坏了。六处修复：

| 问题 | 修复 |
|---|---|
| `make world` 给每个货位加了**编号牌**，level-1 牌底 z=1.02 落在原检测带 (0.17,1.60) 内，牌子连成 2.4 m 大块 | 层带上界改由 `slot_signs.band_z()` 派生 → 1.01 |
| 台面前沿是一整条连续横梁，把整幅货架横向连成一块 | 层带下界抬到 `deck + 0.20`（`Z_DECK_CLEAR`） |
| 左右邻 bay 的货 + 巷道口端板连进本 bay（16 个漏检全是 1.5–3.6 m 宽块） | **先按 bay 横向窗口裁掩码，再做连通域** |
| 半深货位让货物退到前沿之后；对侧巷的货透过空货位能看到（d≈1.75–1.95） | 深度带重标 `(1.33, 1.60)`，上界即"本侧/对侧"分界 |
| 被立柱切开的物体（每段 0.17 m）在尺寸闸门处就被丢掉 | 同货位同深度的碎片**先合并再过闸门** |
| 周转箱渲染成 (49,49,38) 深绿灰，旧判据 `g > r+3` 把它当纸箱 | 改判"非棕色"：`g-r > -3` 且 `g-b > 2` |

**实测（A 巷 48 帧 / 34 个占用货位）**：precision **1.000**、recall **0.912**、
类别 top-1 **0.935**、错格率 **0%** → **PASS**。
样本外（B 巷 39 帧 / 26 个占用货位）：precision 1.000、recall 0.923、top-1 0.958 → **PASS**。

**回归基线**：旧帧用旧标定值必须一直 PASS（15/15、top-1 1.000）：

```bash
.venv/bin/python scripts/seg2_detect.py --frames <2026-10-29 的 npz> \
    --d-lo 1.10 --d-hi 1.55 --z-clear 0.02
```

改动不依赖采集数据本身：`tests/test_seg2_geometry.py` 用合成深度图锁住
"带子上界 < 牌底""窗口裁剪后宽度 ≤1.4 m""1.80 m 的对侧平面必须被拒"这三条。

**采集进度（2026-11-05）**：A 48/48 帧；B 39/48（用 `--fill-gaps` 只补缺的 9 帧）；
C 32 帧断点（失败原因见 A6）；D–F 未采。继续：

```bash
make seg2-robot && make sim          # 另一个终端：make cam-bridge
AISLES=B FILL=1 make seg2-aisles     # B：只补缺的观测，不重抓已采的
```

## A6 · C 巷 SEG-2 失败：观测位被采集车道偏移带偏（2026-11-05 定位）

`scripts/seg2_capture.py` 把 `config/nav.yaml:capture_lane_offsets`（C 巷 0.30 m）
用在了**观测位**上，相机因此不在巷道中线。检测器的货物深度带 `(1.33, 1.60)` 是按
"站在中线、货架面约 1.6 m"标定的；偏 0.30 m 后近侧约 1.3 m、远侧约 1.9 m，两侧都出带。
实测 C 巷 32 帧：precision **0.500**、recall **0.105**；把带放宽到 `(1.05, 1.95)` 后
recall 0.947（precision 0.857、top-1 0.778，仍不达标）——主因是观测位偏移，不是检测代码。
当前 `make seg2-detect-all`（A+B+C）因此是 **P 0.966 / R 0.722 → FAIL**，
`results/seg2.json` 仍只是 A 巷单巷结果。

下一步（未做）：观测位回到巷道中线（偏移只用于**中间航段**，见 `config/nav.yaml` 注释），
或按左右侧补偿深度带；然后重采/重评 C。
